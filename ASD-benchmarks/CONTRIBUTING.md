# Contributing to Principia-100

Help improve the quality of the evidence, the documentation and the tools. Open an [issue](https://github.com/pzqpzq/Principia/issues) or pull request with a stable case ID, the release version and precise source anchors.

## Corrections and reader support

Describe the affected filename or archive member, its SHA-256, your reader version, the observed problem and a minimal reproduction. Propose documentation or read-only reader changes without rewriting accepted source data. Keep derived outputs outside the corpus. Do not execute unreviewed publisher code as part of a reader test.

A changed scientific asset requires a new case revision, updated source and license evidence, checksums, allowlists, inventories, size checks and an explicit changelog entry. Never silently repair missing values, units, orientation or labels in a source file. Preserve the old version's identity and describe the correction.

## New scenarios

A proposal should supply an authoritative public source, an exact version, verifiable redistribution terms, a coherent source-defined selection, native files, measurement dates, available calibration, variables and units, prior analyses, independent validation units and a meaningful quantitative research question. Include controls, unsuccessful runs and negative evidence when part of the selected experiment. Do not select observations because they support an attractive fit.

Target less than 100 MB stored; justify any exception and keep both stored and expanded sizes below 500 MB. A public download alone does not establish redistribution rights. Never include confidential datasets, credentials, private reference findings or identifying operational metadata.

## Scientific reports

Follow the [evaluation protocol](EVALUATION_PROTOCOL.md) and [submission schema](schemas/SUBMISSION.schema.json). State whether the result is reproduction, a validated extension, a novelty candidate or justified abstention. Supply executable equations, source anchors, uncertainty, grouped validation, baselines and falsifying controls. Report resource use and failures. Do not optimize on a supposedly held-out set or omit unfavorable results.

## Versioning and rights

Documentation and tool changes are reviewed separately from scientific claims. Existing source licenses remain controlling; contributors must identify their contribution's terms and retain attribution. The curator documentation is CC BY 4.0 and the tooling is MIT. The benchmark does not award an aggregate discovery score or promise to accept a claimed novel law without scientific adjudication.
